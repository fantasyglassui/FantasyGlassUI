# 13.5 part two Implementation Plan: a beta channel, a check after each game patch, crash reports, learning from many players

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The rest of Behind the scenes: CI can cut a beta that CurseForge files as Beta, the add-on checks itself after each game patch and turns off only what the patch broke, it keeps crash reports with no names if you ask it to, and it keeps (if you ask it to) times you can share so later releases estimate better.

**Architecture:** A seams task first. It adds the shared entries in Core.lua (defaults, commands, help, what's new, a login hook for the check and a skip in the module loop), a section registry for Report a problem, one "click twice" list line, the new files as stubs, the list and TOC entries, and the test regions. Then four parallel tasks, each in its own files and its own smoke region: (E) the beta channel, (F) the patch check, (G) crash reports, (H) learning from many players. A last task merges them, applies every phrase file, regenerates the needs list, adds 13.5 part two to the in-game checklist and runs every check.

**Tech Stack:** Lua 5.1 (WoW: Forever, Interface 16001), GitHub Actions with the BigWigs packager v2, the Python/lupa harness `tests/smoke.py` (lupa 2.8 runs Lua 5.5, so write Lua 5.1 only), pytest, luacheck, bash.

**Spec:** `specs/2026-11-27-13.5-behind-design.md`. Executors read both. Part one (`specs/plans/2026-11-26-13.5.md`) is merged on `release-13.5` and is being reviewed now: never change its code beyond what a task below names.

## Global Constraints

- Every player-facing word goes through `ns:Tr` (or `ns:TrN`, or `ns:Print`, which translates) and exists in all 9 languages (English and de, fr, es, ru, pt, it, ko, zh). Each task writes its phrases to `specs/plans/phrases/135-<task>.json` (`{ "English": [de, fr, es, ru, pt, it, ko, zh] }`). German says "du", never "Sie". **Phrase files are applied at the merge (Task 6), the seams' too:** a task applies its own file only to run `python3 site-src/tools/missing_tr.py <every Lua file it changed>` (which must print nothing), then `git checkout -- FantasyGlassUI_Locales/Locales.lua` before committing.
- No new `ReloadUI` call and no protected calls. Nothing here moves, shows or hides a protected frame.
- Every value read from the game (`GetBuildInfo`, `UnitName`, `GetRealmName`, `GetGuildInfo`, `UnitFactionGroup`, `UnitClass`, `debugstack`, `time`, `GetTime`) goes through `ns:IsSecret` (or `ns.Is` / `ns.Yes`) before it is compared, added or concatenated.
- Long work runs in 4 ms slices (`ns.GoldJob` / `ns.GoldYield()` in the main add-on, `ns.PlannerYield()` in the planner folder); never a yield inside `pcall`, a sort comparator or a `gsub`. The one exception is ruled below (R11: the login check, one pass under 4 ms).
- **Nothing is ever sent by the add-on itself.** No `SendAddonMessage`, `SendChatMessage` or channel message is added anywhere. Codes are only shown, for the player to copy. Every record stays in `FantasyGlassUIDB`.
- Nothing is ever deleted without the player confirming (a "click twice" line, `ns.ConfirmLine`). Nothing in part two deletes anything at login, on a timer or because a switch was changed by a reset or a profile change.
- The website is not touched: nothing under `site-src/` or `docs/` (the phrase tools are only run), no change to the root `CHANGELOG.md`, no version bump (the release does those).
- Commit as DustyMouse (the repo's git config), with no attribution lines. Never push.
- The checks, all of them, before a task reports done: `luacheck .` reports 0 warnings / 0 errors; `cd FantasyGlassUI && python3 ../tests/smoke.py` prints `errors: no errors` twice (readable and SECRET); `python3 tests/forever_audit.py` exits 0; `python3 tests/secretaudit.py` first line ends `; 0 lines compared a hidden value`; `python3 tests/lockaudit.py` lists no blocked line; `python3 -m pytest tests -q` passes.
- **`speedTimed`:** `tests/smoke.py` has `local speedTimed = true` in the 13.5 C region; `secretaudit.py` and `lockaudit.py` rewrite it to `false`, because their code is instrumented and slower. Any timing assertion or timing `print` added here runs only `if speedTimed then ... end`. Never rename that line.
- Smoke tests are `try("<name>", function() ... end)` blocks inside the task's own region, and each region is wrapped in `do ... end` with its own `local function ok(cond, msg) if not cond then error(msg, 2) end end` (the harness is one function: Lua allows 200 locals in it). Each test saves what it changes, runs its body in `pcall`, puts everything back, then `if not fine then error(err, 0) end`, as the 13.5 part one tests do. `printed` (every chat line) and `fireEvent`, `runTimers` are the harness's.
- New planner-folder files start with `local ns = _G.FantasyGlassUI` / `if type(ns) ~= "table" then return end` and end with `ns.FolderFileDone("planner", "<file>")` (tests/test_addon.py::test_folder_files). Every `ns.Planner*` the main add-on uses but does not define is in Folders.lua's folder seams (test_folder_seams_listed).
- A game global the code newly reads goes into `.luacheckrc`'s `read_globals`, by hand, in sorted place (not `regen_rc.py`: it rewrites the whole list and parallel tasks would conflict).

## Review Focus

1. **A Blizzard frame or template that is not there yet at login.** Load-on-demand Blizzard add-ons (the talent window, the auction house, the guild window) create their frames and templates later, so at `PLAYER_LOGIN` many names the add-on uses are legitimately absent. A patch must not make the check turn those parts off. Expected: only a name that was there at this version's last good login and is gone now counts as missing (R7). Test in Task 3 (`13.5 F: a name missing before the patch`).
2. **The game patch and the add-on update arrive together** (the player updates in the CurseForge app after the patch). Expected: nothing is turned off; the new version is trusted and a new baseline is taken (R8). Test in Task 3 (`13.5 F: an update`).
3. **A name in the error text.** A chat link (`|Hplayer:Bob-Realm|h[Bob]|h`), a pet's GUID, a realm with spaces or punctuation ("Argent Dawn", "Mal'Ganis"), a guild name, or a character name that is also an ordinary word: none is kept, and a name with Lua pattern characters never breaks the scrub. Test in Task 4 (`13.5 G: the scrub`).
4. **An error every frame.** An `OnUpdate` that fails 1,000 times while Keep crash reports is on: one record with a count of 1,000, no new chat line after the first, and the crash code itself failing never hides the original error. Test in Task 4 (`13.5 G: an error every frame`).
5. **A beta player and the release.** A player on `13.5.0-beta.2` hears another player's `13.5.0` and is told it is out; players on the release never hear of the beta; what's new still shows once. Test in Task 2 (`13.5 E: beta versions`).

## Rulings (decisions the spec left to the builder)

Each is marked again where it is used.

- **R1 One version check, in a script.** The TOC/Core.lua version check moves from release.yml into `.github/release-version.sh <release|beta> [dir]`, used by both paths. Reason: the workflow cannot be run here; the script can, so the beta rule (`^[0-9]+\.[0-9]+\.[0-9]+-beta\.[0-9]+$`) and the release rule are tested.
- **R2 `[beta]` on main or `beta/**`, `[release]` on main only, never both.** A commit message with both fails the run with "a commit cannot say both [release] and [beta]". The release path does exactly what it does now: same condition, same tag, same packager call. The packager itself makes a tag containing "beta" a CurseForge Beta file and a GitHub prerelease (BigWigs packager release.sh: `*"beta"*` → `file_type="beta"`; `"prerelease": file_type != "release"`), so the workflow passes nothing new to it.
- **R3 How to cut a beta goes in release.yml's header comment and the root README.md, not in RELEASE.md.** Reason: `.pkgmeta`'s `manual-changelog` uploads RELEASE.md to CurseForge as the file's changelog, so instructions there would be published on every file. (There is no build.sh in the repository; the packager is the build.)
- **R4 Beta versions in game.** `ns:ParseVersion` reads `13.5.0-beta.1` as `{ 13, 5, 0, 1 }`; at the same three numbers a release is newer than any beta and beta 2 newer than beta 1. A beta's own `V:` message is ignored by others, as now (the pattern stays `^V:(%d+%.%d+%.%d+)$`), so release players are never told about a beta. The beta line shows once per beta version per account (`root.betaTold = ns.version`). Reason: "the first login says"; a new beta is a new first login.
- **R5 Parts.** A part is a module key (`ns:NewModule("<key>", ...)`): every game name a FantasyGlassUI/*.lua file reads belongs to every module that file defines. The planner folder is the part `planner`, the gold folder `gold`. Files with no module, the options folder and the locales folder are `core`: what `core` misses is reported but never turned off (the settings must still open to switch things). Labels come from FeatureList.lua's `{ "key", "Label" }` entries, `"Route planner"`, `"Ways to make gold"`, `"Fantasy Glass UI"` for core, else the key.
- **R6 What is checked:** the game globals the audit finds the add-on reading, the game's table fields (`C_Timer.After`, `Enum.BagIndex.Bank`), and frame templates (`t:<name>`, through `C_XMLUtil.GetTemplateInfo`). Not frame methods (they need a frame), events, settings or art. Reason: these are what a patch removes, and each is one lookup.
- **R7 Missing means "there before, gone now".** Each version takes a baseline at its first login: the build it saw, kept as `root.lastBuild` (the spec's name), and the set of needed names absent then (`root.health.base.absent`). After a patch, a name is missing only when it is absent now and was not absent in the baseline. Reason: Review Focus 1.
- **R8 An update trusts the new version.** When `ns.version` differs from the baseline's, a new baseline is taken and nothing is turned off, even if the build changed too. Reason: "off until Fantasy Glass UI is updated"; Review Focus 2.
- **R9 The result is kept** (`root.health.result`) and applied quietly at every login of the same build and version: the line prints once, `/fgui health` and Report a problem show it. Reason: the parts stay off "until Fantasy Glass UI is updated", not for one session only; the saved settings are never changed.
- **R10 In a fight at login** (a /reload in combat) the parts start as usual and the check waits (`ns:AfterFight`, quiet). A check that then finds missing parts cannot stop what has started: it keeps the result (applied from the next login) and says so in its own line.
- **R11 The login check is one pass, not sliced,** with each name looked up once, and must take under `ns.HEALTH_BUDGET_MS = 4` ms in the harness (431 globals plus fields and templates today). Reason: it has to finish before the parts start; 4 ms is the slice budget, so it keeps the rule's purpose.
- **R12 A folder part is turned off** through `ns:LoadFolder`, which refuses to load it this session with a line that says why. A module is turned off by the login loop skipping it (`ns.healthOff[key]`), as the conflict check already skips modules. Neither touches `ns.db`.
- **R13 Where "Keep crash reports" sits:** a new section, Accessibility › Help and problems, with a "Show crash reports" button beside it. Reason: Report a problem is a button in the window's foot, not a section; Accessibility is the page the spec names first.
- **R14 Turning crash reports off asks first.** With reports kept, switching off leaves the switch on and opens a list whose last line is "Turn off and clear these %d reports (click twice)"; confirming clears them and switches off. Closing the list changes nothing. With none kept it simply goes off. A reset, a profile change or `/fgui reset` that turns it off keeps nothing new and deletes nothing; `/fgui crashes` still offers to clear. Reason: "cleared the moment it's turned off, after a confirmation", and nothing is deleted without one.
- **R15 What is collected.** Every error that reaches `ns.errors` (a metatable on it catches every append, from every file) and every error `ns:Guard` and `ns:Safe` catch, also after their first one, so the count is true. While the switch is on, Guard and Safe call through `xpcall` with a closure and a handler that takes `debugstack`; while it is off they keep their plain `pcall` (no closure, no cost). No `seterrorhandler`: other add-ons' errors are not ours, and replacing the game's handler can taint.
- **R16 The scrub**, in order: links `|H…|h…|h` become `<link>`; colour and texture codes go; everything up to and including `AddOns\` or `AddOns/` goes and `\` becomes `/` (so `FantasyGlassUI/Skin.lua:313`); any other path (`X:\…`, `/Users/…`, `/home/…`) becomes `<path>`; `Player-…` and `Pet-…` GUIDs become `Player-?` / `Pet-?`; every name of your characters and realms (from `root.chars` keys, `UnitName`, `GetRealmName`, `GetNormalizedRealmName`, each realm also without spaces and without spaces or apostrophes) becomes `<name>` / `<realm>`, your guild (`GetGuildInfo`, and the guilds saved in `root.inventory.guilds`) `<guild>`, and the names of your group, duo partner and friends `<name>`, matched as plain text (no patterns), in their own case anywhere and in any other case as a whole word; then any capitalised `Word-Realm` where Realm is a realm the game can report (yours, `C_AutoComplete.GetAutoCompleteRealms`) becomes `<name>-<realm>`, and with no list from the game any capitalised `Word-Word` that is not a file or a known token; a `WTF\Account\…` path becomes `<path>` (amended at the part two review: P2-I2, P2-I3, P2-M10); then the text is cut to `ns.CRASH_TEXT_MAX = 300` bytes on a character boundary.
- **R17 Distinct and oldest.** Distinct = the same part and the same scrubbed message. "The oldest is dropped first" = the smallest first-seen time. Stack lines: the first `ns.CRASH_STACK_LINES = 4` non-empty lines, each scrubbed.
- **R18 Codes** use the share encoding (`ns.ShareEncode`): `FGC1!` for crash reports, `FGT1!` for times. Both are shown in `ns:ShowTextWindow` (it holds long text; the copy box is one line).
- **R19 `/fgui crashes clear`** opens the list with its clear line, which still needs two clicks. Reason: nothing is deleted without a confirm, typed or not.
- **R20 Where "Help improve time estimates" sits:** the planner window's Records group, after "Show why each step is there", with "Share my times" under it.
- **R21 Root keys outside backups.** Crash reports are `root.crashes`, the times `root.learnTimes`: neither starts with `planner` or `gold`, so part one's backups never copy them. Reason: what the player cleared must not come back with a restore. (`/fgui data` counts them under "Everything else".)
- **R22 A times entry** is `{ k, id, s, c, f, d }`: kind (`"level"`, `"quest"`, `"flight"`, `"boat"`), its key (level number, quest id, `"<node>-<node>"`, crossing id), whole seconds, class token, faction, day. No character key. Each entry keeps its own class and faction because the list is per account (several characters feed it) and flights and boats differ by faction; the code's top-level class and faction are the sharing character's, as the spec lists. A level whose clock was partial is not kept. At most `ns.PLANNER_LEARN_MAX = 500`; past it the first (oldest) entry goes.
- **R23 Shared averages, where they count**, each only while your own record is missing: a quest's time counts as three samples, `(formula + shared * 3) / 4` (the weight your own characters' times get at most); a flight or a boat crossing uses the shared time instead of the distance or the default; time to the next level, while you have fewer than 3 pace samples, is `shared level seconds * (xpMax - xp) / xpMax`. Reason: those are the estimates the three records feed.
- **R24 The "send it in" link** is `ns.PLANNER_SHARE_LINK = "https://fantasyglassui.com/get-started/#share-times"`. The note itself goes on the website at the 13.5 release (Task 6 puts it on the release list); the add-on only shows the address.
- **R25 The averages script** gives each code one vote per entry (the median of that code's values for it; identical codes count once), drops values outside each kind's bounds (quest 10 to 7,200 s, level 60 to 172,800 s, flight 10 to 1,800 s, boat 60 to 900 s), keeps an entry only with at least 3 votes, drops votes outside Tukey's fences (1.5 × the interquartile range, quartiles by `statistics.quantiles(method="inclusive")`), and writes the mean of the rest, rounded to the second.
- **R26 Report a problem's text** keeps its data lines in English, as it does now (the maintainer reads them); the sentences that tell the player what a section holds go through `ns:Tr`.
- **R27 What's new.** One more line in the 13.5.0 entry (exact text in Task 1). Part one's seams test that counts three lines is changed to four.
