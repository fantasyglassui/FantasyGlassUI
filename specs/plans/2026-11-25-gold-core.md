# Gold Advisor, Batch 1 (prices for everyone) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks run in order (2 and 3 both build on 1).

**Goal:** The public part of the gold advisor, shipped in a 12.x update. It adds one price store per auction house (it takes over `ns.root.auctionSeen`), a **Scan prices** button on the auction house that reads the full list in slices, and **Sell now / Hold / Vendor it** hints in item tooltips and on the bag window.

**Architecture:** A new main add-on file `FantasyGlassUI/Prices.lua` owns the store. Every reader goes through its accessor: Economy's tooltip and noting, Auction.lua, Farming.lua and Options/Check.lua. The scan (`PriceScan.lua`) and the hints (`SellHints.lua`) are two more modules in the main add-on, each with its own setting. Nothing in this batch mentions the advisor or the planner, and nothing goes into a `FantasyGlassUI_Gold` folder.

**Tech Stack:** Lua 5.1 (WoW Forever, interface 16001), `C_AuctionHouse.ReplicateItems` / `GetNumReplicateItems` / `GetReplicateItemInfo` (all in `tests/forever_api.json.gz`), `REPLICATE_ITEM_LIST_UPDATE`, the add-on's helpers (`ns:NewModule`, `ns:Guard`, `ns:CreateButton`, `ns:ButtonTip`, `ns:After`, `ns:Tr`, `ns:Coins`, `ns:IsSecret`, `ns.Today`, `ns.DaysBetween`, `ns.AuctionHistoryAdd`, `ns.AuctionUsual`). Tests go in `tests/smoke.py`.

**Spec:** `specs/2026-11-25-gold-advisor-design.md`: Prices, Packaging and release (the "Exception, public early" bullet), Build order 1, and builder-check answer 3.

### Rulings (the spec leaves these open)

**The store and the house key**
- **House key.** `realm .. "|" .. faction`, from `GetRealmName()` and `UnitFactionGroup("player")`. If either can't be read, or is secret, there is no key: notes are dropped and readers see no prices. The Forever API has no way to tell that a neutral auction house is open, so a neutral one shares its faction's key. (This replaces answer 3's "where the game says which one is open": the game does not say. It is noted in the batch notes.)
- **Store shape.** `ns.root.prices = { v = 1, lastScan = <time()>|nil, migrated = true|nil, houses = { [key] = { items = { [itemID] = entry }, scanAt = <time()>|nil, scanItems = n|nil } } }`. An entry keeps the old shape so existing helpers keep working: `{ price, day, hist, listed, listedDay }`.
  - `listed` is the total count listed in the last scan, or 0 if the scan didn't list the item.
  - `listedDay` is that scan's `ns.Today()`.
  - Tables are created only when something is written.
- **Migration.** Runs once, at `auctionMemory` start, when a key exists and `migrated` is not set.
  - Every `ns.root.auctionSeen[id]` entry goes into the current house. If the house already has the item, the entry with the later `day` wins.
  - Then `ns.root.auctionSeen = nil` and `migrated = true`.
  - With no key, it waits for the next login.
- **Forgetting.** `ns.AuctionForget(items, today, 60)` runs on every house's items at start, as it does today.

**The scan**
- **Cooldown.** The server's limit is per account, so the cooldown is `ns.root.prices.lastScan`, shared by every house: 15 × 60 seconds. `lastScan` is set when `ReplicateItems` is called, whether or not the read finishes.
- **Reading a row.**
  - `GetReplicateItemInfo(i)` is read for `i = 0 … n−1` (the index is 0-based). The values used are `count` (3rd return), `buyoutPrice` (10th) and `itemID` (17th).
  - Unit price = `math.floor(buyoutPrice / math.max(1, count))`. A row with buyout 0 (bid only) adds to `listed` but not to the price.
  - A row whose `itemID` isn't a readable number goes on a retry list. That list is read again up to 3 more times, 0.5 s apart, after the main pass. Rows still missing after that are dropped and counted.
- **Writing the result.** This happens after the whole read, in a single pass, so readers never see half a scan. For every item read:
  - `price` = scan lowest, `day` = today
  - `ns.AuctionHistoryAdd(entry, today, price)`
  - `listed` = sum, `listedDay` = today

  Every item already in the house that the scan did not list gets `listed = 0, listedDay = today`, with its price untouched. The house also gets `scanAt = time()` and `scanItems` = how many items were read.
- **Ending early.**
  - The auction house closes during the read: everything read is thrown away, nothing is written, and the message is "The auction house closed before the scan was read: scan again when it allows."
  - No `REPLICATE_ITEM_LIST_UPDATE` within 60 s: "The auction house did not send its list: try again later."
- **Browsing.** Prices seen while browsing still top up the store (Economy's `Note`, now `ns.PriceNote`). They never change `listed`.

**The hints**
- **When each hint shows.** `ns.SellHint` decides, in this order:
  1. `nil` for a bound item, an item with no vendor price that has never been seen, or when there is no house key.
  2. "vendor" when `vendor > 0` and the auction price `p ≤ vendor × 1.15`. The 15% covers the cut and the deposit. `p` is today's price if `entry.day` is today, else the usual price, else `entry.price`.
  3. "vendor" when `vendor > 0`, the item's quality is 2 (uncommon) or lower, and the house was scanned in the last 3 days (`scanAt`), and either the entry is missing or `entry.listed == 0`.
  4. With `ns.AuctionUsual(entry)` giving `u` and `d`, `d ≥ 3`, and `entry.day` at most 1 day old:
     - "sell" when `entry.price ≥ u × 1.15`
     - "hold" when `entry.price ≤ u × 0.80` and `u > vendor × 1.15`
  5. Otherwise `nil`. Prices more than 7 days old never give "sell" or "hold".
- **Bag window marker.** A 10×10 square at the button's BOTTOMLEFT, drawn with `SetColorTexture`:
  - Sell now: green `0.30, 0.85, 0.40`
  - Hold: amber `1, 0.70, 0.20`
  - Vendor it: grey `0.60, 0.60, 0.60`

  It is hidden when the junk coin shows. The tooltip line carries the words, so the colour is never the only sign. `ns:RefreshBagWindow()` runs after a scan is written.

## Review Focus

- **A login whose realm or faction can't be read yet** (early `PLAYER_LOGIN`, a secret value): no migration, no lost prices, no error. Migration happens on the next start that has a key. → Task 1 test.
- **A fight starts mid-read, or the auction house closes mid-read:** the read pauses or is thrown away, and nothing half-written reaches the store. → Task 2 test.
- **A scan list with secret values, `nil` itemIDs, count 0, or buyout 0:** no error. Bid-only rows add to `listed` only, and missing itemIDs are retried. → Task 2 test.
- **An item the scan didn't list:** it shows "Vendor it" only when it is uncommon or lower and has a vendor price. A rare or epic BoE that nobody lists never gets "Vendor it". → Task 3 test.
- **Old characters' saved `auctionSeen` with odd entries** (not tables, no `day`, string prices): the entries are skipped or forgotten, with no error, and every reader (Farming totals, Worth selling, tooltips, /fgui check) still works. → Task 1 test.
