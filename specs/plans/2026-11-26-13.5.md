# 13.5 Implementation Plan: dungeon runs, class quests on time, a speed budget, saved-data tidy and backup

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dungeons become real steps of the planned route, class quests are announced and reached on time, the suite measures the add-on's speed, and the saved data is backed up whole and can be tidied (always asking first).

**Architecture:** One seams task first: it adds the two step kinds (`group`, `dungeon`) to the guide, an `"extra"` hook point to the route's Build (pseudo-hubs that compete with quest hubs and lay their own steps), the shared defaults, what's-new lines, the `/fgui data` command entry, empty new files and the test regions. Then four parallel tasks, each in its own files and its own region of `tests/smoke.py`: (A) dungeon runs, (B) class quests on time, (C) the speed budget, (D) saved-data backup and tidy. A last task merges, applies the translations and runs every check.

**Tech Stack:** Lua 5.1 (WoW: Forever, Interface 16001), the Python/lupa harness `tests/smoke.py`, pytest, luacheck.

**Spec:** `specs/2026-11-26-13.5-design.md` (approved 26 Nov 2026). Executors read both.

## Review Focus

1. **Dying in the dungeon.** Releasing after a wipe puts you at a graveyard outside the instance: the run step must not tick while you are dead or a ghost, only when you leave alive (or come back in and leave again). Test in Task 1 (`13.5 seams: the run step`).
2. **A client in another language.** Instance names from `GetInstanceInfo` are localised ("Die Todesminen"): the run log and the inside mark must match by instance id, never by the English name. Tests in Task 1 (inside mark by id) and Task 2 (`13.5 A: the run time`).
3. **Restoring a backup whose records were still being copied** (the session ended a second after login): a restore puts the settings back and leaves the records as they are, never half a copy. Test in Task 5 (`13.5 D: restore`).
4. **The current character, or a wrong clock.** A character whose last-played time is old because the computer's clock was wrong, or the character you are playing now, is never offered for removal; a character with no last-played time is never offered either. Test in Task 5 (`13.5 D: what the tidy-up finds`).
5. **A plan with a dungeon shared as a plan code.** The website's reader (frozen until the release) rejects unknown step kinds: `group` and `dungeon` steps must travel as `note` so the code still opens on the website. Test in Task 2 (`13.5 A: plan codes`).

## Rulings (decisions the spec left to the builder)

Each is marked again where it is used.

- **R1 Run time.** Default seconds `= (ns.PLANNER_DUNGEON_BASE + ns.PLANNER_DUNGEON_PER_BOSS * bosses) * (1 + max(0, minLevel - 15) / 60)` with BASE = 600, PER_BOSS = 360 (the Deadmines: about 47 min; Ragefire: about 34 min). Your own runs of that dungeon (run log, at least one boss killed): 1 or 2 runs, the average of the default and their mean; 3 or more, the median of the last 5. Reason: a default from level and size, sharpened by the log as the spec asks, without one odd run swinging it.
- **R2 Run log by id.** `ns.RunNew` also keeps the instance id (`r.id`, `GetInstanceInfo`'s 8th value); the planner matches `r.id == d.instance`, falling back to `r.instance == d.name` for runs logged before 13.5. Reason: instance names are localised.
- **R3 Finding a group.** Wait `= ns.PLANNER_GROUP_WAIT (900) * need / 4`, `need = max(0, 5 - have)`, `have = max(group members, 2 with a duo friend, 1)`; in a group of 3 or more the wait is 0. Reason: the spec's 15 minutes is the skip offer; a fuller group waits less.
- **R4 Monster experience.** Kills `= bosses * (ns.PLANNER_DUNGEON_KILLS + 1)` with KILLS = 15; each `ns.PlannerKillXP(level, mob, true)` (elite) times `ns.PLANNER_DUNGEON_SHARE = 0.28` (five players, the classic group bonus 1.4 / 5); `mob = max(minLevel + 2, min(level + 1, maxLevel))`. Reason: the classic group rules, on the planner's own kill formula.
- **R5 Dungeon quests belong to the run.** While dungeon runs are on and the source has dungeons, a quest of a dungeon (`rec.dungeon`, or filed under a dungeon's area) is left out of the quest hubs: it is planned only through its dungeon. A logged one comes back as an ordinary candidate once it is complete, or once its dungeon was run this session. Switch off: 13.0 behaviour. Reason: one quest is never planned twice, and a dungeon quest needs the group and run steps.
- **R6 One dungeon a plan,** the best by rate, offered in every round of the route while a quest hub or the lead-in is still there to beat, or when there is no quest zone at all. Reason: "planned only when it beats the quest areas near you"; with quests dry, the dungeon is the alternative to the dry line.
- **R7 Data.** The list, level ranges and boss counts are `ns.PLANNER_DUNGEONS` (Questie has no level ranges); the entrance is Questie's `ZoneDB:GetDungeonLocation(area)` when Questie has that function and an entry, else the table's. Through `src.dungeons()` on the Questie source only, so no Questie means no dungeon runs. The contract number stays "4" (an optional function is probed, as `IsDungeonZone` is).
- **R8 Plan codes** write `group` and `dungeon` steps with `k = "note"` (their words kept). Reason: the website's reader is frozen until the release.
- **R9 The run step** ticks when you have been inside that instance while the group or run step was current (`st.inside = instance id`, saved, so a /reload inside keeps it) and are now outside it, alive. The group step ticks at 3 members or once you are inside.
- **R10 Skip this dungeon:** for the session (a new session or Plan my route clears it). The panel's menu offers it after `ns.PLANNER_GROUP_SKIP_AFTER = 900` s on the group step, with a line saying so; the step's menu always has it. On a kept route it skips the dungeon's steps (and its quests' steps) instead of planning again.
- **R11 Heads-up.** "always" class quests only (a "fit" one is planned only near the route). Lead 2 levels when the start is on another continent or more than `ns.PLANNER_CLASS_FAR_SECONDS = 600` s away, else 1. Chat once per character per quest (`root.planner[key].classTold[id]`); the panel line shows while you are in the lead window. Reason: chat is the one-time notice, the panel line is the standing advice.
- **R12 The hold** (no flying away in the level before) applies only while you are on the start's continent: the zone is picked among that continent's maps when it has any hub, and a rank entry on another continent (a dungeon too) is left out. Within a continent nothing more: travel is already counted. Reason: the spec's own example; a player elsewhere makes the trip as the lead-in at the quest's level.
- **R13 Prerequisites** of a due class quest are planned one level deep (the quest itself unlocks after that hand-in's replan).
- **R14 Speed limits** = 4 × the slowest of three measured runs (both modes), rounded up to 10 ms, written in smoke.py with the measurements and the date. Slices: no planner or gold slice over 3 × its 4 ms budget. A flake is a missing yield to find, never a limit to raise.
- **R15 Slice measuring** is two numbers the runners keep (`ns.plannerSliceMax`, `ns.goldSliceMax`): one subtraction a slice in the game.
- **R16 Backups.** Records are every root key `guides`, `guideState`, `^planner`, `^gold`; never `prices`. The update and daily backups carry them; the reset backup does not (a reset touches one profile's settings); the restore backup gets the current records moved into it. Copied in 4 ms slices on `ns.GoldJob` (the only slice runner in the main add-on; the planner's is in a load-on-demand folder); `recordsDone` marks a finished copy. Over `ns.BACKUP_RECORDS_MAX_KB = 4096`, the largest stores are left out and named in `recordsLeftOut`. A restore moves the backup's tables into place (no copy; the reload that follows writes them out as separate tables).
- **R17 The tidy-up finds:** characters (not you) whose `root.charInfo[key].last` (else `root.planner[key].lastSeen`) is more than 180 days old: their `planner`, `plannerLevels`, `guideState` and `goldChars` entries (not alts, bags or other features' records: those have their own forget). Price entries whose newest of `day`, `listedDay`, `seenDay` is more than 30 days old, and a house left empty with `scanAt` older than 30 days. Another character's finished trip (replaced by what it paused). A character's state following a written guide that no longer exists. `written[name]` places of deleted guides.
- **R18 Confirming:** the tidy list's last line, clicked twice within `ns.DATA_CONFIRM_SECONDS = 10`.
- **R19 Release notes:** the 13.5.0 what's-new entry and the README's Commands row go in now; no version bump and no root CHANGELOG entry (the release does those).
