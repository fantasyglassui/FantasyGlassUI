## The add-on cannot send anything
A WoW add-on has no internet. Anything shared leaves only because the player copies a code and shares it themselves. That is also the privacy line: **nothing is ever sent by itself**, and every record is kept in SavedVariables on the player's own computer.

## 1. A beta channel
- **CI.** release.yml learns a second trigger: a commit with `[beta]` in its message, on main or on a `beta/*` branch.
  - The version is read from the TOC and must look like `13.5.0-beta.1`.
  - The workflow tags that version and runs the packager with the beta release type, so CurseForge files it as Beta. It also makes a GitHub prerelease.
  - `[release]` stays exactly as it is.
- **In game.** When the version holds "beta", the first login says "You are on a beta of Fantasy Glass UI. Thank you for testing! Report a problem includes it." The Report a problem code names the version, which already includes "beta".
- **Docs.** RELEASE.md says how to cut a beta. The website's Get started gets a line on switching to Beta in the CurseForge app. That line goes on the site only at the 13.5 release.
- **Not this:** an in-game switch for beta. CurseForge decides which file a player gets.

## 2. A check after each game patch
- The add-on already stores the client build in the version info that forever_audit checks against. At login, it reads `GetBuildInfo()` and compares it with `root.lastBuild`.
- **When the build changes (a patch):**
  1. Run a light health check: every API, frame and template the add-on depends on, taken from one list kept in the add-on (`ns.HEALTH_NEEDS`, generated by a test from forever_audit's data so it never drifts).
  2. For each part whose needs are missing, turn off only that part for this session through its own switch path, without changing the saved setting.
  3. Print one line: "After the game's update, these parts are off until Fantasy Glass UI is updated: X, Y."
- `/fgui health` runs the check on demand and lists the results.
- The result is kept, and Report a problem includes it.
- No ReloadUI. No check during combat: it waits.

## 3. Crash reports, if you want
- **The switch:** "Keep crash reports", off by default, in Accessibility & help (or wherever Report a problem lives).
- **When it's on:** the add-on's existing error catching (`ns:Guard` and the error collector) keeps each distinct error. It records:
  - the message, with paths trimmed to the add-on's own files;
  - the stack's top lines;
  - the version, the client build and the add-on part;
  - a count and a first-seen and last-seen time.
- **Names are removed wherever the add-on can find them.** The text is scrubbed of anything after "Player-" GUIDs, of your characters', realms' and guild's names in every form the game writes, of the names in your group, your duo partner's and your friends', and of any other "Name-Realm". A message can still hold a name the add-on cannot know, so the add-on says: "Names are removed wherever the add-on can find them. Look over the report before you share it." (Amended at the 13.5 part two review, P2-I3; the website's Roadmap preview, which says "with no names", changes at release to match.)
- At most 30 distinct reports; the oldest is dropped first.
- **Report a problem** gets a "Crash reports" line that copies them as one code, with what is included written out above it. `/fgui crashes` lists them, and `/fgui crashes clear` empties the list.
- **When it's off:** nothing is kept beyond today's session behaviour, and the old reports are cleared the moment it's turned off, after a confirmation.

## 4. Learning from many players
- **The switch:** "Help improve time estimates", off by default, in the planner window.
- **When it's on:** the planner's own records are kept in a separate list, with no names, class only, at most 500 entries:
  - level times;
  - each quest's time from accept to hand-in;
  - flight and boat times.
- **Share my times** in the planner window makes a code: version, class, faction and these entries. What it holds is written out, and a link points to the website's "send it in" note (the Discord channel or the contact address).
- **Inside the add-on:** a data file of shared averages, `ns.PLANNER_SHARED_TIMES`, which starts empty. When it has an entry for a quest or level, the planner uses it until the player's own record exists. That way, players' submissions can improve estimates in later releases.
- A small script in tools/ turns a folder of codes into that data file, as averages with outliers dropped, for the maintainer.
- **When it's off:** nothing new is kept. Turning it off offers to clear what was kept, after a confirmation.
